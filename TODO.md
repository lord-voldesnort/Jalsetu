# MVP outcome tracker

- [x] **Two-role demo access and privacy:** The demo has exactly Farmer and Water Manager roles, one clearly labelled illustrative service area, one manager, and three farmers. Demo passwords are hashed and sessions expire. There is no public sign-up. Each API call enforces the role and service-area scope; a farmer can only read or change their own requests, ledger, deliveries, acknowledgements, and discrepancy reports. The manager can read and act only in the assigned service area.
- [x] **Supply periods and requests:** A manager can create and close non-overlapping supply periods with a declared pool in m³; the dashboard shows declared supply, total requested, total approved, and remaining. Farmers submit positive requested m³, fixed purpose, start/end dates inside one open period, and a short reason; optional area/crop are labelled self-declared and unverified. Invalid fields and uncovered dates receive clear errors. Same-farmer requests with the same purpose and overlapping dates require explicit duplicate confirmation. Closing a period rejects new requests and expires undecided requests with a system event.
- [x] **Request status and reasoned decisions:** Farmers can edit or withdraw their own undecided requests, and answer a clarification with a note. Managers can request clarification, approve, partially approve, or reject only with a nonempty reason. Illegal transitions are refused. Requested, approved, and delivered quantities remain separate. Manager quantity edits require a reason. Any approved-quantity correction is a new reasoned event referencing the earlier decision. The interface exposes farmer edit/withdraw controls and manager approved-quantity correction controls.
- [x] **Allocation support:** On a declared period pool, the manager sees all three deterministic policy outcomes: proportional, urgency-first (required start date then submission time), and equal-share/max-min. Quantities are whole m³; no recommendation exceeds a request or remaining pool. Fractional remainders are assigned by largest remainder, with submission-time tie-break. The manager chooses the rule and retains final authority. A template explanation states its calculation; recommendation inputs, rule, outputs, explanation, and final decision are captured for history. No claim of machine learning, objective optimality, or objective fairness is made.
- [x] **Budget enforcement and period rules:** Decisions are checked against remaining approved volume inside one serialized database transaction; concurrent approvals cannot jointly exceed the pool. Lowering supply below existing approvals is blocked; an increase requires a reasoned history event. Overrides are off by default. Decisions cannot be approved against a closed period.
- [x] **Delivery and shared event ledgers:** Managers can record multiple partial deliveries with quantity, time, and note; cumulative delivered volume is shown. Above-approved delivery is flagged and requires a note. Farmers acknowledge a delivery or report a discrepancy. A manager resolves a discrepancy without rewriting the original delivery or allocation. Farmer and manager ledgers show consistent facts from the same timestamped actor-attributed event records.
- [x] **Append-only audit trail:** Events cannot be updated or deleted through database triggers/permissions, and each request’s events are hash-chained. A verification view reports intact or broken and states that this is tamper evidence, not protection from a full database administrator. Loading, error, empty, and phone-sized states are supported.
- [x] **Product scope and honest presentation:** The primary experience is the water request/allocation workflow; no Inspector role, map, synthetic farm registry, satellite/soil claim, forecast, or physical-delivery proof is presented as part of the MVP. Illustrative demo data, unverified farmer data, policy trade-offs, and prototype limitations are disclosed.
- [x] **English and Marathi interface:** The sign-in and dashboard provide English/Marathi language controls; the selected language is persisted in browser storage and translated interface text is rendered in that language.
